# Правила работы с проектом

## О проекте

Это пользовательская интеграция ZONT WebSocket для Home Assistant. Исходный код
интеграции находится в `custom_components/zont_ws`, автоматические тесты — в
`tests`, локальная среда Home Assistant — в `.devcontainer`.

## Подход к архитектуре

- Следуйте актуальной документации разработчика Home Assistant и применимым
  правилам Integration Quality Scale:
  <https://developers.home-assistant.io/docs/core/integration-quality-scale/>.
- Предпочитайте штатные механизмы, helpers и жизненный цикл Home Assistant
  собственной инфраструктуре. Отступайте от распространённых практик только
  при наличии технической причины, которую можно объяснить в коде или
  документации.
- Разделяйте знание о внешнем протоколе и адаптацию к Home Assistant. Нижние
  слои не должны зависеть от сущностей, реестров и жизненного цикла верхних;
  зависимости направляйте в одну сторону и передавайте внешние ресурсы явно.
- Передавайте состояние между слоями как целостный неизменяемый снимок. Один
  владелец отвечает за обновление данных, а потребители не должны изменять их
  или наблюдать частично применённое обновление.
- Держите точки входа платформ и config entry тонкими: они связывают штатные
  механизмы Home Assistant с предметной логикой, но не становятся местом её
  реализации.
- Проектируйте интеграцию асинхронной и неблокирующей. Не выполняйте
  блокирующие операции в event loop; используйте рекомендованные Home Assistant
  способы их изоляции:
  <https://developers.home-assistant.io/docs/asyncio_blocking_operations/>.
- Ресурсы интеграции должны иметь понятный жизненный цикл: корректно
  создаваться, выгружаться и освобождаться без фоновых задач, подписок или
  соединений, оставшихся после unload.
- Временная недоступность устройства должна обрабатываться предсказуемо и
  восстанавливаться автоматически. Ошибки авторизации должны приводить к
  понятному пользовательскому сценарию, а повторяющиеся сбои не должны
  засорять журнал.
- Сохраняйте обратную совместимость пользовательской конфигурации и публичных
  возможностей. Если совместимость сохранить нельзя, предусмотрите явную
  миграцию и опишите изменение.
- Существенное поведение сопровождайте автоматическими тестами. Диагностика и
  документация должны помогать пользователю разобраться в состоянии
  интеграции, не раскрывая секретные данные.

Не закрепляйте архитектурные решения только потому, что так устроена текущая
реализация. При изменениях сверяйтесь с актуальными рекомендациями Home
Assistant и выбирайте принятый в экосистеме подход.

## Среда разработки

Основная среда разработки — devcontainer из `.devcontainer/devcontainer.json`.
Откройте репозиторий командой **Dev Containers: Reopen in Container** и
выполняйте проектные команды внутри контейнера. Не создавайте `.venv` и не
устанавливайте зависимости проекта на хосте.

Для запуска локального Home Assistant используйте:

```bash
python -m homeassistant --config .devcontainer/config
```

Runtime-данные из `.devcontainer/config`, включая базы данных, журналы и
lock-файлы, не должны попадать в репозиторий. Не добавляйте в код, тесты,
диагностику и документацию пароли, токены и другие секреты.

## Язык и документация

README, локализация и пользовательские тексты интеграции ведутся только на
русском языке. Идентификаторы Python, имена файлов, ключи протокола и другие
технические интерфейсы сохраняйте в принятом для них формате.

### Документация протокола

Если для работы нужно уточнить устройство или поведение протокола ZONT,
изучайте документацию в следующем порядке:

1. `docs/ZONT_API_MQTT_WebSocket_v2.md`;
2. `docs/API контроллеров ZONT. Формат обмена сообщениями с контроллерами ZONT через JSON.md`;
3. `docs/ZONT_MQTT.md`.

Обновляйте документацию вместе с пользовательским поведением. Версию в
`manifest.json` повышайте для функционального релиза, но не для изолированного
изменения документации или `AGENTS.md`.

## Проверки

Перед завершением изменения выполните внутри devcontainer:

```bash
python -m pytest -q
ruff check .
ruff format --check .
python -m homeassistant --script check_config --config .devcontainer/config
```

Добавляйте или обновляйте тесты для изменённого поведения. Не исправляйте
посторонние изменения в рабочем дереве и перед передачей результата проверяйте
`git diff --check`.
