# ZONT для Home Assistant

Пользовательская интеграция Home Assistant для локального WebSocket-интерфейса
контроллера ZONT. Она поддерживает одно авторизованное соединение, создаёт
сущности подключения и диагностики контроллера, обнаруживает аналоговые входы,
адаптеры цифровой шины котла и цифровые датчики температуры, публикует входящие
сообщения как события Home Assistant и предоставляет действия для универсальных
команд ZONT.

Планы развития интеграции описаны в [ROADMAP.md](./ROADMAP.md).

## Требования

- Home Assistant 2026.8 или новее;
- локальный IPv4- или IPv6-адрес контроллера ZONT;
- имя пользователя и пароль контроллера.

## Установка

1. Скопируйте каталог `custom_components/zont_ws` в
   `/config/custom_components/zont_ws` вашего Home Assistant.
2. Перезапустите Home Assistant.
3. Откройте **Настройки → Устройства и службы → Добавить интеграцию**.
4. Выберите **ZONT**, укажите IP-адрес и учётные данные контроллера.

Интеграция принимает именно IP-адрес, без протокола, порта и пути. Адрес
локального WebSocket-интерфейса `ws://<IP>/ws` формируется автоматически.

При добавлении интеграция запрашивает у контроллера серийный номер, модель,
модель платы и версию прошивки. Серийный номер используется как стабильный
идентификатор, поэтому ответы на команды `#S54?` и `#S7?` обязательны для
завершения настройки.

При переходе с версии 0.2 удалите старую запись интеграции и добавьте контроллер
заново. Это необходимо для перехода от временного идентификатора записи к
серийному номеру устройства. Домен интеграции и действия `zont_ws.*` не
изменились.

После настройки модель и версия прошивки обновляются в фоне при запуске и после
восстановления соединения. Последние полученные значения сохраняются в Home
Assistant, поэтому обновление сведений не задерживает загрузку интеграции.

Через действие **Перенастроить** в настройках интеграции можно изменить
IP-адрес, имя пользователя и пароль. Если пароль менять не требуется, оставьте
поле нового пароля пустым.

## Сущности контроллера

Интеграция добавляет к устройству ZONT следующие сущности:

- **Подключение** — состояние локального WebSocket-соединения;
- **Связь с облаком** — состояние облачного подключения по данным
  `#S224?`;
- **Канал связи** — все активные каналы GSM, Wi‑Fi и Ethernet по данным
  `#S224?`;
- **Напряжение питания** — значение `#S6?` в вольтах;
- **Перезагрузить** — кнопка отправки команды `SRESTART?`.

Сведения о модели запрашиваются после каждого подключения, а изменяемые
показатели контроллера — раз в минуту. Первый опрос выполняется в фоне и не
задерживает загрузку интеграции. При восстановлении WebSocket-соединения данные
обновляются сразу.

Кнопка **Перезагрузить** перезапускает физический контроллер. Интеграция не
разрывает WebSocket сама: диагностические сущности становятся недоступными,
когда контроллер фактически закрывает соединение, и восстанавливаются
автоматически после его запуска.

## Аналоговые входы

Интеграция обнаруживает аналоговые входы `type=0` и создаёт для каждого из них
отдельное дочернее устройство с именем из настроек ZONT. Модель устройства
соответствует назначенному в контроллере подтипу: датчику давления, движения,
протечки, влажности, дискретному входу или другому документированному пресету.

Для каждого входа создаются две сущности:

- **Значение** — числовое поле `v` с единицей, которую передал контроллер;
- **Сработка** — бинарное состояние поля `trig` с подходящим классом устройства
  Home Assistant.

Для дискретных и охранных входов основным состоянием является **Сработка**.
Их сырое числовое **Значение** создаётся как отключённая по умолчанию
диагностическая сущность и при необходимости включается в настройках
устройства. У измерительных входов обе сущности включены по умолчанию.

Поддерживаются все документированные подтипы `stype=0…21` и единицы: вольты,
килоомы, бары, километры в час, обороты в минуту, литры, литры в час и проценты.
Неизвестный подтип безопасно отображается как универсальный аналоговый вход.
Если контроллер не передал отдельное поле, соответствующая сущность остаётся
недоступной. При `a=0` обе сущности становятся недоступными, сохраняя последние
полученные значения до восстановления входа.

## Адаптеры цифровой шины

Интеграция обнаруживает адаптеры цифровой шины `type=6` и создаёт для каждого
из них отдельное дочернее устройство с именем, заданным в ZONT. Доступные
показатели запрашиваются раз в минуту и обновляются сразу при получении
WebSocket-сообщения от контроллера.

Для адаптера создаются только те сущности, значения которых контроллер
фактически передал:

- **Температура теплоносителя**;
- **Температура ГВС**;
- **Температура обратки**;
- **Модуляция**;
- **Давление теплоносителя**;
- **Состояние** — «Выключен», «Работает» или «Ошибка»;
- **Код ошибки**.

Температура обратки, модуляция и давление предусмотрены протоколом, но могут не
поддерживаться конкретным котлом или адаптером. В таком случае лишние сущности
не создаются. При временной недоступности адаптера уже созданные сущности
становятся недоступными и восстанавливаются автоматически.

## Цифровые датчики температуры

Объекты `type=1` создаются как отдельные дочерние устройства контроллера с
именами из настроек ZONT. Для каждого объекта интеграция добавляет сенсор
температуры в градусах Цельсия. Например, объект с именем `Т Спальня` получает
сущность `sensor.t_spalnia_temperature`.

Поле `a` из ответа контроллера определяет доступность датчика. При временном
отключении последнее значение сохраняется, но сущность становится недоступной
до восстановления датчика. Поле `trig` для цифровых термодатчиков пока не
используется, поскольку его назначение для `type=1` не подтверждено
документацией.

## Действия

### `zont_ws.send_command`

Отправляет одну команду. Обязательные поля: `id` от 0 до 999999 и непустое
значение `cmd`. Если запрошен ответ действия, результат имеет следующий вид:

```yaml
response: <декодированный ответ ZONT>
```

### `zont_ws.send_bulk`

Последовательно отправляет непустой список команд и останавливается при первой
ошибке. Если запрошен ответ действия, результат имеет следующий вид:

```yaml
responses:
  - id: 4107
    response: <декодированный ответ ZONT>
```

При запуске Home Assistant интеграция ожидает подключения и авторизации не
более пяти секунд. Если контроллер недоступен, Home Assistant откладывает
загрузку интеграции и повторяет попытку штатным механизмом. До первого успешного
подключения бинарный сенсор подключения недоступен.

После успешной загрузки последующие обрывы уже не задерживают Home Assistant:
бинарный сенсор переходит в состояние «Выключено», а интеграция восстанавливает
соединение в фоне с увеличивающейся задержкой до 30 секунд. Диагностические
сущности на время обрыва становятся недоступными. Действия сразу завершаются
ошибкой; после восстановления сенсор снова переходит в состояние «Включено», а
данные контроллера запрашиваются заново.

## События

Входящие сообщения, не являющиеся ответами на команды, публикуются как событие
`zont_ws_event`:

```yaml
device_id: <идентификатор устройства Home Assistant>
payload: <декодированное значение JSON или исходный текст>
```

## Разработка

Откройте репозиторий в VS Code и выполните команду **Dev Containers: Reopen in
Container**. Контейнер автоматически установит закреплённые зависимости и
подключит интеграцию к локальной конфигурации Home Assistant.

Проверки внутри контейнера:

```bash
python -m pytest -q
ruff check .
ruff format --check .
python -m homeassistant --script check_config --config .devcontainer/config
```

Запуск тестового Home Assistant на порту 8123:

```bash
python -m homeassistant --config .devcontainer/config
```
