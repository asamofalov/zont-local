# Локальный протокол ZONT WebSocket

Этот документ объединяет сведения о локальном WebSocket-интерфейсе
контроллеров ZONT, которые используются или исследованы в проекте ZONT Local.
Он не является официальной спецификацией производителя. Поддержка внутренних
команд зависит от модели и версии прошивки.

## Уровни подтверждённости

Для каждой команды указан максимальный достигнутый уровень и основание:

| Уровень | Значение |
| --- | --- |
| **L3 — проверено** | Команда и результат проверены на контроллере H-1V.02 PRO, плата 700, прошивка 625 |
| **L2 — документировано** | Команда описана в официальной документации ZONT, но не проверена в рамках проекта |
| **L1 — клиент** | Команда найдена в официальном веб-клиенте ZONT или его source map |
| **L0 — гипотеза** | Сведения получены из стороннего кода, косвенного наблюдения или пока не имеют достаточного подтверждения |

`L3` подтверждает поведение только исследованного контроллера и не гарантирует
поддержку другими моделями и прошивками. Если команда имеет несколько
оснований, они перечисляются вместе.

Обозначения риска:

- **чтение** — не изменяет состояние контроллера;
- **запись** — изменяет состояние объекта или конфигурацию;
- **опасно** — может удалить данные, изменить связь, перезапустить устройство,
  вызвать физическое действие либо расход средств.

## 1. Транспорт и сессия

### 1.1. Подключение и авторизация

Локальный адрес имеет вид `ws://<ip>/ws`. Для TLS может использоваться `wss`,
если его поддерживает конкретная конфигурация контроллера.

| Команда | Ответ | Уровень | Риск |
| --- | --- | --- | --- |
| `{"user":"<username>","pass":"<password>"}` | `{"auth":200}` при успехе, `{"auth":401}` при отказе | **L3**, официальная документация и проверка | запись |

Учётные данные передаются открытым текстом внутри WebSocket. Пароль, имя
пользователя, сетевые идентификаторы и ответы чувствительных системных команд
нельзя выводить в журнал или диагностику.

Контроллер может присылать push-состояния до и после авторизации. До успешного
`auth=200` их нельзя считать состоянием настроенной сессии.

### 1.2. Сопоставление сообщений

В протоколе нет общего ID запроса:

- `ids` соответствует запросу `req_ids`, но не содержит запрошенный тип;
- `scmdres` не содержит исходную команду;
- `cmdres` сопоставляется по `id` или встречавшемуся варианту `Id`;
- объектные push-сообщения могут прийти между запросом и ответом.

Поэтому все запросы постоянного клиента выполняются через общую FIFO-очередь:
следующая команда отправляется только после ответа или ошибки предыдущей.
Ожидание очереди не входит в таймаут ответа, который начинается после
фактической отправки. В одном эксперименте восемь последовательных `req_ids`
получили ответы в порядке отправки, но FIFO со стороны контроллера не является
документированной гарантией.

Входящие push-сообщения не проходят через очередь и обрабатываются сразу.
Запросы, поставленные в очередь на прежнем WebSocket-соединении, после
переподключения не отправляются: актуальные чтения и синхронизация формируются
заново верхними слоями. Односторонняя команда перезапуска занимает очередь
только до завершения отправки, поскольку получение её ответа не гарантировано.

Разрыв соединения отменяет ожидающие ответы. После переподключения временно
неудачные запросы выполняются заново. Ответ `#Sxxx:!` означает отсутствие
данных для конкретной команды в текущий момент и не должен навсегда запрещать
её последующие опросы.

## 2. Базовые JSON-команды

| Команда | Назначение и ответ | Уровень | Риск |
| --- | --- | --- | --- |
| `{"req_ids":<type>}` | Получить `{"ids":[...]}` для типа объекта | **L3**, официальная документация и проверка | чтение |
| `{"req_ids":255}` | Получить общий список известных ID без границ типов | **L3**, официальная документация и проверка | чтение |
| `{"id":<id>,"req_state":0}` | Получить состояние объекта | **L3**, официальная документация и проверка | чтение |
| `{"id":<id>,"cmd":<value>}` | Выполнить команду; результат `{"id":<id>,"cmdres":<code>}` | **L3**, официальная документация и проверка | запись |
| `{"name":"<name>","type":<type>,"cmd":<value>}` | Найти объект по имени либо создать его и выполнить команду | **L3** для типов 0 и 1; **L2** для остальных разрешённых типов | запись |
| предыдущая команда с `"stype":<subtype>` | Создать объект нужного подтипа | **L3** для type 0, stype 19/20; **L2** как общий механизм | запись |
| `{"scmd":"<command>"}` | Выполнить текстовую системную команду; ответ в `scmdres` | **L3**, официальный пример и проверка | зависит от вложенной команды |

`cmdres=0` означает, что команда принята, но не доказывает достижение конечного
состояния. После управляющей команды следует проверить объект через
`req_state` или дождаться подходящего push.

Ответ вида `{"id":<id>,"req_state":0,"failed":1}` означает, что состояние
объекта сейчас недоступно. ID может по-прежнему присутствовать в `req_ids`.
Такой ответ не является ошибкой всего соединения.

### 2.1. Автосоздание

Официальная MQTT-документация заявляет автосоздание начиная с прошивки 500 для
типов `0`, `1`, `2`, `10`, `14`, `15`, `16`, `17`, `27` и `53` — **L2**.
Практически проверены:

| Команда | Поведение | Уровень | Риск |
| --- | --- | --- | --- |
| `{"name":"HA - Температура","type":1,"cmd":"1 24.1"}` | Создаёт или обновляет виртуальный цифровой датчик температуры | **L3**, также **L2** | запись |
| `{"name":"HA - Контакт","type":0,"stype":20,"cmd":"0 0 180"}` | Создаёт виртуальный НЗ-вход | **L3** | запись |
| `{"name":"HA - Контакт","type":0,"stype":19,"cmd":"0 0 180"}` | Создаёт виртуальный НР-вход | **L3** | запись |

В имени нет стабильного внешнего идентификатора, поэтому перед повторной
настройкой следует привязываться к уже созданному ID, если он известен.

## 3. Типы объектов и состояния

### 3.1. Типы JSON API

| `type` | Объект | Подтверждение |
| ---: | --- | --- |
| 0 | Аналоговый вход | **L2**, состояния проверены **L3** |
| 1 | Цифровой датчик температуры DS18 | **L2**, проверено **L3** |
| 2 | Охранная зона | **L2**, проверено **L3** |
| 6 | Адаптер цифровой шины котла | **L2**, проверено интеграцией |
| 8 | Радиодатчик | **L2**, без проверки на реальном радиомодуле |
| 10 | Пользовательский элемент | **L2**, stype 0–2 проверены **L3** |
| 14 | Реле | **L2**, проверено **L3** |
| 15 | Смеситель | **L2**, чтение проверено **L3** |
| 16 | Контур отопления | **L2**, проверено **L3** |
| 17 | Насос | **L2**, чтение и принятие команд проверены **L3** |
| 27 | NTC-термодатчик | **L2**, поддержан интеграцией |
| 255 | Любой тип, только для `req_ids` | **L2**, проверено **L3** |

В конфигурации `#Z` официального клиента встречаются также типы `3–5`, `7`,
`9`, `11–13`, `18–22`, `24–31`, `33–40`, `42–43`, `45–53` и `56–59`.
Это **L1**: наличие сериализатора конфигурации не подтверждает поддержку JSON
API, конкретной моделью или текущей прошивкой.

### 3.2. Подтипы

Подтипы `type=10` — **L2**, stype 0–2 дополнительно **L3**:

| `stype` | Назначение |
| ---: | --- |
| 0 | Статус входа/выхода |
| 1 | Простая кнопка |
| 2 | Сложная кнопка |
| 3 | Аналоговый регулятор, не проверен |

Подтипы `type=16` — **L2**, stype 0, 1 и 3 дополнительно **L3**:

| `stype` | Назначение |
| ---: | --- |
| 0 | Котловой контур |
| 1 | ГВС |
| 2 | Охладительный контур |
| 3 | Потребительский контур |

Подтипы `type=0` — **L2**: `0` без пресета, `1` давление 5 бар, `2` давление
12 бар, `3` дверь, `4` ИК с контролем шлейфа, `5` дым, `6` протечка, `7` ИК
без контроля шлейфа, `8` термостат, `9/10` авария котла +/−, `11` зажигание,
`12` скорость, `13` обороты, `14` дискретный вход, `15` тревожная кнопка,
`16` расход топлива, `17` влажность, `18` давление 6 бар, `19` НР, `20` НЗ,
`21` давление 10 бар. Виртуальные stype 19/20 проверены **L3**. Stype 3 без
аппаратного входа не подходит для виртуального бинарного датчика — **L3**.

Подтипы `type=8` — **L2**: `2/3` брелоки, `4` радиореле, `5` термометр, `6`
радио-DUT, `7` модуль капота, `8` радиометка, `10` протечка, `11` движение,
`12` удар, `13` комбинированный термометр, `14` электроэнергия, `15` внешний
термометр, `16` расход воды/газа, `17` розетка, `18` температура/влажность,
`19/20` радиометки, `23` радиопанель. На реальном радиомодуле не проверены.

### 3.3. Общие поля состояния

| Поле | Значение |
| --- | --- |
| `id`, `type`, `stype`, `name` | Идентификатор, тип, подтип и имя |
| `t` | Температура либо текст состояния — зависит от типа |
| `v`, `u`, `trig` | Аналоговое значение, код единицы, признак срабатывания |
| `a` | Доступность или активность источника — зависит от типа |
| `c`, `s`, `m`, `m_id`, `f` | Текущее значение, уставка, режим, ID режима и неисправность контура |
| `water`, `dhw`, `return`, `modul`, `press`, `state`, `err` | Данные адаптера цифровой шины |
| `h`, `b`, `r` | Влажность, батарея и радиопараметры — для поддерживающих их радиодатчиков |

Поля зависят от типа. Неизвестное поле нельзя интерпретировать по аналогии с
другим объектом только из-за совпадения имени.

## 4. Формат `cmd` по типам

| Объект | Команда | Назначение | Уровень | Риск |
| --- | --- | --- | --- | --- |
| type 0 | `0 N T` | Значение `N` в десятых долях вольта, активно `T` секунд | **L3**, также **L2** | запись |
| type 0 | `1 N T` | Значение `N` как `float`, активно `T` секунд | **L2** | запись |
| type 1/27 | `N` или `0 N` | Температура в децикельвинах | **L2** | запись |
| type 1/27 | `1 N` | Температура в °C как `float` | **L3** для type 1, также **L2** | запись |
| type 2 | `0`, `1`, `2` | Снять, поставить или инвертировать охрану | **L3** для 0/1; **L2** для 2 | запись, физическое действие |
| type 14 | `0`, `1` | Задать логическое состояние реле | **L3**, также **L2** | запись, физическое действие |
| type 15 | `1`, `2`, `3`, `4` | Полностью открыть, закрыть, открыть или закрыть на шаг | **L2** | опасно, физическое действие |
| type 16 | `<temperature_dk>` | Ручная уставка, `°C = dk / 10 - 273` | **L3**, также **L2** | запись |
| type 16 | `<mode_id>` | Применить режим к одному контуру | **L3** | запись |
| type 17 | `0`, `1` | Запросить выключение или включение насоса | **L3**, также **L2** | опасно, физическое действие |
| type 10, stype 1 | `1` | Выполнить действие простой кнопки | **L3** | запись, зависит от действия |
| type 10, stype 2 | `0`, `1` | Установить состояние сложной кнопки | **L3**, также **L2** | запись, зависит от действия |
| type 10, stype 3 | `2,N` | Установить аналоговое значение | **L2** | запись |
| mode type 20 | `1` | Применить режим глобально | **L3** через JSON `cmd`, также **L2** | запись |

Для виртуальных type 0 значение `T` является heartbeat: без обновления источник
становится недоступным. Для НЗ (`stype=20`) значения `0` и `20` дают
`trig=0/1`; для НР (`stype=19`) — `trig=1/0`. Это проверено на устройстве.

Команды насоса могут быть приняты, но автоматика контура и настроенный выбег
способны оставить физический выход включённым. Поэтому `cmdres=0` нельзя считать
подтверждением остановки.

## 5. Системные команды `scmd`

### 5.1. Используемые и проверенные команды

| Команда | Ответ и назначение | Уровень | Риск |
| --- | --- | --- | --- |
| `#S54?` | `#S54:<serial>` — серийный номер | **L3**, официальный клиент и проверка | чтение, чувствительные данные |
| `#S7?` | `#S7:<model> <board> <firmware>` | **L3**, также **L2** | чтение |
| `#S4?` | `#S4:<level> <registration> <operator>` | **L3**, официальный клиент и проверка | чтение |
| `#S6?` | `#S6:<voltage_dv> <source>` | **L3**, официальный клиент и проверка | чтение |
| `#S198?` | Wi-Fi: состояние, RSSI, MAC, IP, маска, шлюз | **L3**, официальный клиент и проверка | чтение, чувствительные данные |
| `#S205?` | Ethernet: MAC, IP, маска, шлюз, подключение | **L3** для ответа `!`, формат из официального клиента | чтение, чувствительные данные |
| `#S208?` | Параметры Wi-Fi | **L3**, наблюдение | чтение, секретные данные |
| `#S224?` | Четыре флага: облако, GSM, Wi-Fi, Ethernet | **L3**, наблюдение | чтение |
| `SDATE?` | Дата и время контроллера | **L3**, наблюдение; также официальный клиент | чтение |
| `SGETALLSTATES?` | `GETALLSTATES=<count>`; возвращает число оперативных состояний, но не публикует их | **L3** | чтение |
| `SCFG_RELOAD_REQ?` | `CFG_RELOAD=ok` и повторная публикация состояний | **L3** | запись, перечитывание конфигурации |
| `SRESTART?` | Перезапуск контроллера без обязательного ответа перед разрывом | **L3** в рабочем сценарии интеграции; исходно сторонний код | опасно |
| `#S217?` / `#S217=<mqtt-url>` | На проверенной прошивке отвечает `#S217:!`; назначение адреса MQTT следует из клиента | **L3** для неподдержки, **L1** для назначения | опасно, изменение связи |
| `#S221?` | На проверенной прошивке отвечает `#S221:!`; предположительно связано с MQTT | **L3** для неподдержки, **L0** для назначения | чтение |

Форматы проверенных состояний:

- `#S198:<connected_state> <rssi> <mac> <ip> <mask> <gateway>`; значение
  `connected_state=8` наблюдалось при подключённом Wi-Fi;
- `#S205:<mac> <ip> <mask> <gateway> <connected>`;
- `#S4:<level 0..31> <registration 0..5> <operator>`; состояния регистрации:
  не зарегистрирован, домашняя сеть, поиск, отказ, неизвестно, роуминг;
- `#S6:<decivolts> <source>`; `0` наблюдается для основного питания, другое
  числовое значение интерпретируется клиентом как батарея;
- `#S224:<cloud> <gsm> <wifi> <ethernet>`, каждый флаг равен `0` или `1`.

проверена форма `#S224?`.

указано иначе, их уровень — **L1**. Это формат файла конфигурации, а не
доказательство безопасности тех же строк как `scmd`.

| `#S12=<ussd> <threshold>` | USSD-запрос баланса и порог | **L1** |

| `#S180=<value>`, `#S181=<value>` | Интерфейс и параметры диагностики A300 | **L1** |

| `#S203=<apn>`, `#S204=<password>` | APN и сервисный пароль | **L1**, строки наблюдались; секреты |
| `#S206=<value>` | Настройки GSM-уведомлений | **L1**, строка наблюдалась |
| `#S207=<phone> <encoded_date>` | Сервисный телефон и закодированная дата | **L1**, строка наблюдалась |
| `#S208=<ssid>,<password>,<enabled>` | Wi-Fi | **L1**, чтение проверено **L3**; секрет |
| `#S209=<0_or_1>` | Использование резервной батареи | **L1**, строка наблюдалась |
| `#S210=<mask1>,<mask2>,<mask3>,<mask4>` | Четыре 31-битные маски; точное назначение битов неизвестно | Наличие **L3**, семантика **L0** |
| `#S211=<id>,<title>,<version>` | Штатная конфигурация устройства | **L1**, строка наблюдалась |
| `#S212=<flags>` | Флаги серверных настроек | **L1**, строка наблюдалась |
| `#S214=<name>` | Имя локальной подсети | **L1**, строка наблюдалась |
| `#S217=<address>` | Адрес MQTT | **L1**, на проверенной прошивке запись не поддержана **L3** |
| `#S218=<ssid>,<password>` | Точка доступа Wi-Fi | **L1**, строка наблюдалась; секрет |
| `#S219='<value>'` | Наблюдалось значение `zont`; точное назначение неизвестно | Наличие **L3**, семантика **L0** |
| `#S220=<serial> <hw_type> 1` | Запуск обновления прошивки модуля расширения | **L1**, опасно |
| `#S221=<value>` | Точное назначение неизвестно; предположительно связано с MQTT | **L0**, запрос вернул `!` **L3** |
| `#S222=<0_or_1>` | Режим «только 2G» | **L1**, строка наблюдалась |
| `#S223=<y>,<x>` | Географические координаты | **L1**, строка наблюдалась; чувствительные данные |
| `#S224?` | Флаги облака и каналов связи | **L3**; формат записи не подтверждён |
| `#S225=<10_times_step>` | Шаг температуры, умноженный на 10 | **L1** |
| `#S226=<0_or_1>` | Запрет добавления устройств | **L1** |

Надёжных сведений о `#S215` нет. Запись сетевых адресов, паролей, APN, MQTT,
Wi-Fi и серверных параметров может лишить контроллер связи.

## 6. Внутренние объекты `#Y` и `#Z`

### 6.1. Чтение

| Команда | Ответ | Уровень | Риск |
| --- | --- | --- | --- |
| `#Y<id>?` | `#Y<id>$...` — оперативное внутреннее состояние | **L3**, также официальный клиент | чтение |
| `#Z<id>?` | `#Z<id>:<type>,...` — конфигурация объекта | **L3**, также официальный клиент | чтение |

Ответы являются позиционными структурами. Внутри встречаются строки в
кавычках и массивы, поэтому обычный `split(',')` неприменим.

#### Контур отопления, type 16

Для `#Y<circuit>?` проверены поля:

| Индекс | Значение | Уровень |
| ---: | --- | --- |
| 0 | Расчётная температура теплоносителя, децикельвины | **L3** |
| 1 | Активная уставка, децикельвины; `0` при выключенном контуре | **L3** |
| 5 | ID применённого режима; `0` при ручной уставке | **L3** |
| 6 | ID источника текущей температуры | **L3** |
| 7 | Битовые флаги состояния | **L3**, расшифровка частично из клиента |
| 8 | Список применимых режимов type 20 | **L3** |
| 9 | Предыдущее или связанное целевое значение; точный смысл неизвестен | **L0** |
| 10 | Временной параметр; точные единицы не подтверждены | **L0** |

Флаги поля 7: `1` запрос тепла, `2` блокировка, `4` выключен, `8` неисправность
датчика, `16` внешний термостат, `32` запрос внешнего термостата, `64`
резервный котёл, `128` летний режим, `256` антилегионелла, `512` запрет котла
расписанием, `1024` постоянная работа котла, `2048` запрос тепла потребителем,
`4096` цель антилегионеллы достигнута, `8192` каскад, `16384` ошибка
управления. Значение `32768` наблюдалось кратковременно, но не расшифровано.

Для `#Z<circuit>?` интеграцией используются следующие позиции — **L3** для
проверенных ответов, расшифровка сверена с официальным клиентом:

| Индекс | Значение |
| ---: | --- |
| 0–2 | Type 16, имя и stype |
| 3–4 | Минимальная и максимальная температура теплоносителя, децикельвины |
| 5–6 | Основной и резервный датчики воздуха |
| 7–8 | Основной и резервный датчики теплоносителя |
| 11 | Регистр настроек |
| 13 | Внешний термостат |
| 15 | ID ПЗА; `0` и `255` означают отсутствие |
| 16 | Источник тепла |

Два младших бита регистра настроек задают базовое регулирование: `0` по
воздуху, `1` воздух + PID, `2` по теплоносителю. Бит `128` означает, что ПЗА
используется только для запроса тепла, а бит `1048576` — ведомый контур.
Точная полная схема зависит от прошивки; неизвестные позиции изменять нельзя.

#### Режим отопления, type 20

`#Z<mode>?` содержит имя режима, параллельные массивы ID контуров и уставок в
децикельвинах, а также номер режима. Нулевая уставка означает выключение
соответствующего контура. `#Y<mode>?` не показывает, применён ли режим сейчас.
Оба вывода проверены на устройстве — **L3**.

#### Пороговые значения датчиков температуры

В `#Z<sensor>?` пороги хранятся в децикельвинах. Для type 1 верхний и нижний
пороги находятся в позициях `3/4`, для type 8 и type 27 — в `4/5`. Эти позиции
проверяются интеграцией — **L3** для использованных конфигураций. Ответы
неподдерживаемых типов нельзя разбирать по тем же индексам.

#### Реле, насос и смеситель

- `#Z<relay>?` содержит аппаратный выход и флаги конфигурации; биты `1` и `8`
  связаны с инверсией. `#Y<relay>?` содержит флаги: `1` активен, `2`
  неисправность, `4` тест, `8` ожидание — **L3**, расшифровка частично **L1**.
- `#Z<pump>?` содержит, среди прочего, выбег в миллисекундах; значение `300000`
  соответствует пяти минутам. Остальные позиции не подтверждены — **L3** для
  наблюдения.
- `#Y<mixer>?` содержит направление и флаги: `1` полностью открыт, `2`
  полностью закрыт, `32` неисправность датчика, `64` неисправность выхода,
  `128` не удалось установить положение. Биты `4/8/16` остаются служебными или
  неизвестными — **L3** для наблюдений, **L1** для части расшифровки.

#### Охранные зоны и пользовательские элементы

- `#Y<zone>?` наблюдался как три значения, но публичное состояние надёжнее
  читать из JSON-полей `s` и `trig` — **L3**.
- Для type 10 `#Y` повторяет состояние `s`; `#Z` содержит тексты состояний и
  связанные объекты. Управление интеграция выполняет через JSON `cmd` — **L3**.

### 6.2. Запись из официального клиента

| Команда | Назначение | Уровень | Риск |
| --- | --- | --- | --- |
| `#Y<mode_id>=1` | Применить режим глобально | **L1** | запись |
| `#Y<circuit_id>=<mode_id>` | Применить режим к одному контуру | **L3**, официальный клиент и проверка | запись |
| `#Y<mode_id>=2 [duration [hour minute]]` | Временный режим | **L1** | запись |
| `#Y<mode_id>=3` | Сбросить временный режим | **L1** | запись |
| `#Y<circuit_id>=<temperature_dk>` | Ручная уставка контура | **L1**; эквивалентный JSON cmd проверен **L3** | запись |
| `#Y<circuit_id>=,,,<temperature_dk>` | Альтернативная ветвь установки температуры | **L1**, семантика условия неясна | запись |
| `#Y<scenario_id>=1` | Запустить сценарий | **L1** | опасно, зависит от сценария |
| `#Z<object_id>=29,'<name>'` | Добавить радиобрелок | **L1** | запись |
| `#Y<prev_module_id>=*,0`, затем `#Y<module_id>=*,120` | Добавить радиодатчики | **L1** | опасно, радиоконфигурация |
| `#Y<object_id>=0/1` | Разрешить добавление кнопок брелока или датчиков 433 МГц | **L1** | запись |
| `#S18=10/20` | Разрешить или запретить добавление ключей Touch Memory | **L1** | запись |
| `#Y<object_id>=255` | Очистить радиомодуль | **L1** | **опасно, удаление данных** |
| `#Y<zone_id>=<onguard>` | Изменить охрану зоны | **L1** | опасно, физическая охрана |
| `#Y<element_id>=<state>[,<value>]` | Изменить веб-элемент | **L1** | запись |
| `#Y<object_id>=0..3` | Нормальное/тестовое состояние насоса или реле | **L1** | опасно, физический выход |
| `#Y<tap_id>=*,0/1` или `#Y<tap_id>=*,255` | Тест смесителя либо выход из теста | **L1** | опасно, физический выход |
| `#Y<object_id>=0/1` | Запустить или остановить калибровку | **L1** | опасно |
| `#Y<object_id>=16/0` | Разрешить или запретить внешнюю панель | **L1** | запись |

возвращает пустой список и ничего не отправляет — **L1**.

## 7. Push-сообщения и обновление конфигурации

Контроллер отправляет JSON push в том же формате, что и `req_state`. Проверены
push для контуров, реле, смесителя, пользовательских элементов, температурных
и аналоговых датчиков — **L3**. Push охранной зоны не наблюдался: изменение зоны
надёжно подтверждается адресным `req_state`.

Бинарный push вида `#Y<id>$...` наблюдался при изменениях контуров и смесителя.
При создании объекта приходил `#Z<id>=...`, а следующая свободная позиция могла
обозначаться `#Z<id>=*` — **L3**. В JSON-режиме отдельный входящий
`CFG_RELOAD_REQ` поймать не удалось.

`SCFG_RELOAD_REQ?` проверен как активный запрос перечитывания конфигурации, а не
как пассивное уведомление. `SGETALLSTATES?` возвращает только счётчик и не
заменяет `req_ids`, `req_state`, `#Y` или `#Z`.

## 8. Кратко о бинарном режиме

Официальный локальный клиент умеет передавать текстовые команды бинарными
WebSocket-кадрами. Например, бинарная строка `#Y<id>?` получает бинарный ответ
`#Y<id>$...`. Это проверено на устройстве — **L3**. JSON-обёртка `scmd`
предоставляет доступ к тем же текстовым командам и используется интеграцией.

Официальная документация также описывает бинарный файловый протокол:

| Код запроса/ответа | Операция | Уровень | Риск |
| --- | --- | --- | --- |
| `0x40 / 0x41` | Открыть файл | **L2** | чтение или запись |
| `0x42 / 0x43` | Закрыть файл | **L2** | запись |
| `0x44 / 0x45` | Записать блок с подтверждением | **L2** | опасно, изменение файлов |
| `0x46 / 0x47` | Записать блок без подтверждения | **L2** | опасно, изменение файлов |
| `0x48 / 0x49` | Прочитать блок | **L2** | чтение |
| `0x4A / 0x4B` | Получить список файлов | **L2** | чтение |
| `0x4C / 0x4D` | Удалить файл | **L2** | **опасно, удаление данных** |
| `0x4E / 0x4F` | Создать каталог | **L2** | запись |
| `0x56 / 0x57` | Форматировать файловую систему | **L2** | **опасно, потеря данных** |

Интеграция не использует файловый протокол. Форматирование, удаление и запись
файлов не должны становиться универсальными действиями Home Assistant.

## 9. Правила безопасной реализации

- Сериализовать `req_ids` и `scmd`, потому что ответы не содержат достаточной
  корреляции.
- Различать `ids`, `cmdres`, `scmdres`, объектные состояния и push.
- После `cmdres=0` проверять фактическое состояние объекта.
- Не считать `failed=1`, `#Sxxx:!` или таймаут отдельной команды отказом всего
  контроллера.
- После переподключения повторять нужные чтения и полный контрольный опрос.
- Не публиковать необработанные `scmdres`: они могут содержать пароли, номера,
  координаты, сетевые адреса и идентификаторы оборудования.
- Не предоставлять команды удаления, конфигурации сети, радиомодуля,
  файловой системы, звонков и SMS без отдельного безопасного сценария.
- Не приписывать неизвестным позиционным полям смысл без воспроизводимого
  эксперимента или подтверждения официальным источником.
