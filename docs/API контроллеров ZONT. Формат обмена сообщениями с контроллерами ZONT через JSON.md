## Адрес WebSocket

Запросы через HTTP WebSocket отправляются по адресу:

```text
http://ip_address/ws
```

Для приборов с HTTPS:

```text
https://ip_address/ws
```

## Авторизация

Запрос:

```json
{
  "user": "user_name",
  "pass": "user_password"
}
```

`user_name` и `user_password` — имя пользователя и пароль из настроек
пользователей контроллера.

Ответ:

```json
{
  "auth": 200
}
```

Коды ответа:

| Код | Результат |
| --- | --- |
| `200` | Успешная авторизация |
| `401` | Ошибка авторизации |

## Запрос списка ID объектов

```json
{
  "req_ids": 16
}
```

`req_ids` содержит тип объектов (`int`), соответствующий типам объектов в
конфигурации.

Ответ:

```json
{
  "ids": [20494, 20496, 8362]
}
```

## Запрос состояния объекта

```json
{
  "id": 20496,
  "req_state": 0
}
```

Ответ:

```json
{
  "Id": 20496,
  "type": 16,
  "name": "Имя объекта"
}
```

Содержимое ответа зависит от типа объекта. Поля состояния совпадают с полями
для MQTT-протокола ZONT.

### Типы объектов

| `type` | Тип объекта |
| ---: | --- |
| `0` | Аналоговый вход |
| `1` | Цифровой датчик температуры DS18… |
| `2` | Охранная зона |
| `6` | Адаптер цифровой шины |
| `8` | Радиодатчик |
| `10` | Пользовательский элемент управления |
| `14` | Реле |
| `15` | Смеситель |
| `16` | Контур отопления |
| `17` | Насос |
| `27` | NTC-термодатчик |
| `255` | Любой тип |

### Подтипы пользовательских элементов — `type=10`

Для `WEB_ELEMENT` добавляется поле `stype`:

| `stype` | Тип элемента управления |
| ---: | --- |
| `0` | Статус |
| `1` | Простая кнопка |
| `2` | Сложная кнопка |
| `3` | Аналоговый регулятор |

### Подтипы контуров отопления — `type=16`

Для `HEATING_CIRCUIT` добавляется поле `stype`:

| `stype` | Тип контура |
| ---: | --- |
| `0` | Котловой контур |
| `1` | ГВС |
| `2` | Охладительный контур |
| `3` | Контур потребителя |

### Подтипы аналоговых входов — `type=0`

Для `ANALOG_INPUT` добавляется поле `stype`:

| `stype` | Тип датчика |
| ---: | --- |
| `0` | Аналоговый вход без пресета |
| `1` | Датчик давления 5 бар |
| `2` | Датчик давления 12 бар |
| `3` | Датчик открытия двери |
| `4` | ИК-датчик движения с контролем шлейфа |
| `5` | Датчик дыма |
| `6` | Датчик протечки |
| `7` | ИК-датчик движения без контроля шлейфа |
| `8` | Комнатный термостат |
| `9` | Авария котла + |
| `10` | Авария котла - |
| `11` | Вход «Зажигание» |
| `12` | Датчик скорости |
| `13` | Датчик оборотов двигателя |
| `14` | Дискретный вход |
| `15` | Тревожная кнопка |
| `16` | Датчик расхода топлива |
| `17` | Датчик влажности |
| `18` | Датчик давления 6 бар |
| `19` | Дискретный вход НР |
| `20` | Дискретный вход НЗ |
| `21` | Датчик давления 10 бар (с версии 475) |

### Подтипы радиодатчиков — `type=8`

Для `RADIO_SENSOR` добавляется поле `stype`:

| `stype` | Тип датчика |
| ---: | --- |
| `2` | Трёхкнопочный брелок |
| `3` | Четырёхкнопочный брелок |
| `4` | Радиореле блокировки |
| `5` | Радиотермометр |
| `6` | Радиодут |
| `7` | Модуль капота: концевик, термометр, замок капота и сирена |
| `8` | Радиометка |
| `10` | Радиодатчик протечки |
| `11` | Радиодатчик движения |
| `12` | Радиодатчик удара |
| `13` | Радиотермометр из трёх датчиков и концевого контакта |
| `14` | Радиодатчик расхода электроэнергии |
| `15` | Внешний радиодатчик температуры |
| `16` | Радиодатчик расхода воды и газа |
| `17` | Радиорозетка 220 В |
| `18` | Радиодатчик температуры и влажности |
| `19` | Радиометка с акселерометром |
| `20` | Радиометка с аккумулятором |
| `23` | Радиопанель (радиотермостат) |

## Управление объектом

```json
{
  "id": 20496,
  "cmd": 3130
}
```

Ответ:

```json
{
  "Id": 20496,
  "cmdres": 0
}
```

`cmd` имеет тот же формат, что и в MQTT-протоколе ZONT.

## Управление устройством

```json
{
  "scmd": "#S7?"
}
```

Ответ:

```json
{
  "scmdres": "#S7:H2000PRO…"
}
```
