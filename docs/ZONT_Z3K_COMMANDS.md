# Терминальные команды Z3K из веб-клиента ZONT

Этот документ фиксирует команды и форматы обмена, найденные в исследованной
версии официального веб-клиента ZONT. Они находятся не в одном месте, а в
нескольких независимых слоях:

- 25 структурированных действий, которые `z3kCommandToText` преобразует в
  терминальные строки;
- встроенный справочник терминала и команды обслуживания устройства;
- запросы, которые локальный клиент выполняет автоматически;
- сериализаторы параметров `#S` и объектов `#Z` для файла `config.txt`;
- бинарный протокол работы с файловой системой контроллера.

Это инвентаризация исследованной сборки веб-клиента, а не доказательство
полноты внутреннего командного языка прошивки. Терминал принимает произвольный
текст, поэтому в прошивке могут существовать команды, которые веб-клиент не
использует и не упоминает.

Источники:

- [source map `vendor-9f6f3e.js.map`](https://my.zont.online/webpack-beta/zont/vendor-9f6f3e.js.map);
- [соответствующий bundle `vendor-9f6f3e.js`](https://my.zont.online/webpack-beta/zont/vendor-9f6f3e.js);
- source map приложения, в котором виден вызов преобразователя из локального
  клиента: [`app-288339.js.map`](https://my.zont.online/webpack-beta/zont/app-288339.js.map).

Исследование выполнено 9 августа 2026 года. Хеши файлов относятся к конкретной

## Как команды доходят до контроллера

Официальный локальный клиент выполняет следующую последовательность:

```text
структурированная Z3K-команда
  -> z3kCommandToText(command)
  -> одна или несколько терминальных строк
  -> z3k_protocol.send_command(command_string)
```

При работе через исследуемый WebSocket API терминальная строка помещается в
поле `scmd`:

```json
{"scmd":"#Y9171=20501"}
```

Ответ приходит в `scmdres`. Команда также может вызвать обычные push-состояния
изменившихся объектов. Поскольку `scmdres` не содержит отдельного ID запроса,
терминальные команды следует выполнять последовательно.

Обозначения в таблицах:

- `<object_id>` — `command.object_id`;
- `<mode_id>` — `command.command_args.mode_id`;
- логические аргументы преобразуются функцией JavaScript `Number`: `false` в
  `0`, `true` в `1`;
- список из нескольких строк означает, что клиент отправляет каждую из них как
  отдельную терминальную команду.

## Отопление и сценарии

### `SelectHeatingMode`

Глобально применяет режим отопления. `object_id` является ID режима.

```text
#Y<mode_id>=1
```

Эквивалент для режима `20501`:

```json
{"scmd":"#Y20501=1"}
```

### `SelectHeatingModeForCircuit`

Применяет режим только к выбранному контуру. `object_id` является ID контура,
а `command_args.mode_id` — ID режима.

```text
#Y<circuit_id>=<mode_id>
```

На исследованном контроллере экспериментально подтверждена команда:

```json
{"scmd":"#Y9171=20501"}
```

Она применила режим `20501` только к контуру `9171`, установила его уставку из
конфигурации режима и вызвала push с `m_id=20501`.

Режим должен входить в список применимых режимов контура, возвращаемый в поле
с индексом `8` ответа `#Y<circuit_id>?`.

### `SelectHeatingModeTemporary`

Включает временный режим. `object_id` является ID режима.

Без длительности:

```text
#Y<mode_id>=2
```

Если `command_args.duration` имеет ненулевое значение:

```text
#Y<mode_id>=2 <duration>
```

Если одновременно `command_args.hour` имеет ненулевое значение, добавляются
час и минута:

```text
#Y<mode_id>=2 <duration> <hour> <minute>
```

Это точное поведение исследованного сериализатора. Единицы `duration` и
семантика времени должны быть дополнительно сверены с пользовательским API до
использования в интеграции.

### `ResetHeatingModeTemporary`

Сбрасывает временное применение режима. `object_id` является ID режима.

```text
#Y<mode_id>=3
```

### `TargetTemperature`

Устанавливает ручную целевую температуру контура. `object_id` является ID
контура, `command_args.value` — значением в градусах Цельсия.

Обычный формат:

```text
#Y<circuit_id>=<temperature_dk>
```

Сериализатор вычисляет значение без явного округления:

```text
temperature_dk = 10 * (temperature_c + 273)
```

Если одновременно передано истинное `firmware_version` и значение температуры
больше `136`, используется альтернативный формат:

```text
#Y<circuit_id>=,,,<temperature_dk>
```

Назначение этой ветви и значений выше `136` требует дополнительного
исследования. Обычная температура отопительного контура в неё не попадает.

### `RunScenario`

Запускает сценарий. `object_id` является ID сценария.

```text
#Y<scenario_id>=1
```

## Радиоустройства и охрана

### `AddFob`

Создаёт или настраивает радиобрелок. Использует `object_id` и
`command_args.name`.

```text
#Z<object_id>=29,'<name>'
```

Сериализатор не показывает дополнительного экранирования одинарных кавычек в
имени.

### `AddRadiosensors`

Переводит радиомодуль в режим добавления датчиков.

Если передан ненулевой `command_args.prevModuleId`, сначала формируется:

```text
#Y<prev_module_id>=*,0
```

Затем всегда формируется:

```text
#Y<object_id>=*,120
```

Таким образом, результат может содержать одну или две терминальные команды.
Смысл значения `120` по одному сериализатору не установлен.

### `AllowFobButtonsAdd`

Разрешает или запрещает добавление кнопок брелока:

```text
#Y<object_id>=<0_or_1>
```

Значение берётся из `command_args.shouldAllow`.

### `AllowSensors433Add`

Разрешает или запрещает добавление датчиков 433 МГц:

```text
#Y<object_id>=<0_or_1>
```

Значение берётся из `command_args.shouldAllow`.

### `AllowTMKeysAdd`

Управляет разрешением добавления ключей Touch Memory. `object_id` не
используется.

```text
#S18=10
```

формируется при `command_args.shouldAllow=true`, иначе:

```text
#S18=20
```

### `ClearRadioModule`

Отправляет команду очистки радиомодулю:

```text
#Y<object_id>=255
```

Команда потенциально разрушительна и не должна выполняться без отдельного
подтверждения назначения конкретного объекта и ожидаемых последствий.

### `ZoneOnGuard`

Изменяет состояние охраны зоны:

```text
#Y<object_id>=<onguard>
```

Значение берётся напрямую из `command_args.onguard`; сериализатор не приводит
его к логическому типу.

## Веб-элементы и исполнительные устройства

### `ChangeWebElementState`

Использует `command_args.state` и опциональное `command_args.value`.

Для состояний `0` и `1`:

```text
#Y<object_id>=<state>
```

Для остальных состояний:

```text
#Y<object_id>=<state>,<value>
```

### `SetTestPumpOrRelay`

Управляет тестовым состоянием насоса или реле. Итоговое значение вычисляется
так:

```text
value = Number(isOn) | (Number(isTest) << 1)
```

| `isTest` | `isOn` | Значение | Терминальная команда |
| --- | --- | ---: | --- |
| `false` | `false` | `0` | `#Y<object_id>=0` |
| `false` | `true` | `1` | `#Y<object_id>=1` |
| `true` | `false` | `2` | `#Y<object_id>=2` |
| `true` | `true` | `3` | `#Y<object_id>=3` |

### `SetTestTap`

Управляет тестовым состоянием крана или смесителя.

При `command_args.isTest=true`:

```text
#Y<object_id>=*,<0_or_1>
```

Значение берётся из `command_args.isOn`. При `isTest=false` формируется:

```text
#Y<object_id>=*,255
```

### `StartStopCalibration`

Запускает или останавливает калибровку:

```text
#Y<object_id>=<0_or_1>
```

Значение берётся из `command_args.toStart`.

### `ExternalPanel`

Разрешает или запрещает внешнюю панель:

```text
#Y<object_id>=16
```

формируется при `command_args.shouldAllow=true`, иначе:

```text
#Y<object_id>=0
```

### `ChangeAnalogOutputValue`

В исследованной сборке преобразователь зарегистрирован, но всегда возвращает
пустой список:

```text
[]
```

То есть локальный клиент не отправляет терминальную команду для этого
`command_name`.

## Связь, диагностика и системные операции

### `DialUser`

Инициирует звонок на номер из `command_args.telephone`:

```text
DIAL=<telephone>
```

### `SendSMSToUser`

Отправляет SMS. Используются `command_args.telephone` и
`command_args.message`:

```text
SMS=<telephone> <message>
```

Сериализатор не показывает дополнительного экранирования пробелов или
служебных символов в сообщении.

### `LoadA300DiagAvailableParams`

Запрашивает доступные диагностические параметры A300:

```text
#S62?
```

`object_id` и `command_args` не используются.

### `UpdateA300DiagInterface`

Изменяет диагностический интерфейс A300. Используется
`command_args.value`:

```text
#S180=<value>
```

### `RemoveObject`

Удаляет объект конфигурации:

```text
#Z<object_id>~
```

Это разрушительная операция. Её нельзя предоставлять через универсальный
сервис Home Assistant без явного пользовательского сценария и дополнительных
защитных мер.

### `RestartDevice`

Перезапускает устройство:

```text
RESTART
```

Команда не использует `object_id` или `command_args`. Она отличается от
команды `SRESTART?`, найденной ранее в сторонней интеграции; совместимость и
поведение обеих форм следует проверять отдельно для конкретной прошивки.

## Запросы локального клиента

Локальная страница не использует `GETALLSTATES?` для регулярного опроса. Раз в
минуту она последовательно отправляет четыре системных запроса, а затем
запрашивает состояния известных ей объектов:

| Команда | Назначение в клиенте |
| --- | --- |
| `#S198?` | состояние Wi-Fi |
| `#S205?` | состояние сетевых интерфейсов |
| `#S6?` | напряжение питания |
| `#S4?` | состояние GSM |
| `#Y<object_id>?` | текущее состояние объекта |

`#Y<object_id>?` отправляется только для типов объектов, для которых официальный
парсер знает формат состояния: аналоговый вход, контур, реле, насос, смеситель,
проводной/аналоговый/радиодатчик, адаптер котла, радиомодуль, охранная зона,
DUT, аналоговый выход, веб-элемент и режим отопления.

В исходном `Z3KProtocol` перед каждой текстовой командой добавляется один пробел
как часть локального бинарного транспорта. В JSON-команде `scmd` этот пробел
добавлять не требуется:

```json
{"scmd":"#Y9171?"}
```

Локальное соединение также распознаёт входящее сообщение `CFG_RELOAD_REQ`.
Это уведомление контроллера с требованием перечитать конфигурацию, а не команда,
которую клиент регулярно отправляет.

## Встроенный справочник терминала

В исходном файле
`console/shared/components/panels/terminal/terminal-command.ts` есть два набора
подсказок: Z3K и более старый ZTC/ZTH. Это именно справочник пользовательского
терминала: наличие записи подтверждает, что веб-интерфейс показывает такой
шаблон, но не всегда подтверждает точный синтаксис или поддержку конкретной
прошивкой.

### Z3K

| Запись в справочнике | Назначение |
| --- | --- |
| `SDATE?` | запрос времени и даты |
| `GETALLSTATES?` | запрос всех актуальных состояний |
| `#S7?` | тип устройства, аппаратная модель и прошивка |
| `#S213?` | ICCID SIM-карты |
| `#S216?` | IMEI прибора |
| `#S222?=` | режим «только GPRS» |
| `#S223?=` | геопозиция |
| `#S224?=` | подключение к серверу и используемый канал связи |
| `#S200?` | адрес сервера |
| `#S201?` | порт сервера |
| `#S202?` | логин и пароль устройства |
| `#S204?` | сервисный пароль |
| `DIAL=` | тестовый звонок; после `=` указывается номер |
| `SMS=` | тестовая SMS; после номера ставится пробел и текст |
| `Restart` | перезапуск терминала, как он подписан в справочнике |
| `#S15=1` | принять изменения и перечитать конфигурацию |
| `#P87=0` | отключить все журналы устройства |

Строки `#S222?=`, `#S223?=` и `#S224?=` выглядят как совмещение форм запроса
`?` и записи `=`. Именно так они записаны в справочнике веб-клиента; отправлять
их буквально без проверки не следует. Для `#S224` на исследованном
контроллере подтверждён обычный запрос `#S224?`. Сериализаторы конфигурации
подтверждают формы записи `#S222=...` и `#S223=...`.

Для перезапуска структурированный преобразователь и код обновления прошивки
используют `RESTART` в верхнем регистре. Поэтому `Restart` в таблице следует
считать подписью/примером терминала, а подтверждённой командой этой сборки —
`RESTART`.

### ZTC/ZTH и совместимые старые терминалы

| Запись в справочнике | Назначение |
| --- | --- |
| `#S54` | серийный номер, начиная с версии профиля 217 |
| `#S19?` | IMEI и ICCID, опционально |
| `#S62` | состояние системы и диагностика двигателя, начиная с профиля 240 |
| `#S8` | разрешённые для SMS-доступа номера; `?` — запрос, `=` — запись |
| `ReConnecT` | переподключение после `LOGPAS=`, `IPA=` или `IPP=` |
| `IPA=` | установка адреса сервера |
| `IPP=` | установка порта сервера |
| `LOGPAS?` | проверка логина и пароля |
| `GPS?` | информация о местоположении |
| `time?` | время устройства |
| `date?` | дата устройства |
| `gsm?` | уровень GSM-сигнала |
| `POWER?` | напряжение питания |

У `#S54` и `#S62` в справочнике нет суффикса `?`, хотя в других частях клиента
для чтения используется именно запрос. На исследованном устройстве подтверждён
`#S54?`, а `z3kCommandToText` формирует `#S62?`.

Команды этого подраздела нельзя автоматически переносить на Z3K: регистр и
синтаксис у старого протокола значимы. Например, переключатель сервера для
старых устройств отправляет `ReStarT`, а не `RESTART`.

## Команды обслуживания локального клиента

Эти строки найдены не в справочнике, а непосредственно в выполняемом коде:

| Команда или шаблон | Когда используется |
| --- | --- |
| `CFG_RELOAD` | после записи или импорта `config.txt` |
| `#S15=1` | после форматирования файловой системы |
| `RESTART` | после загрузки основной прошивки |
| `#S220=<serial> <hw_type> 1` | запуск обновления прошивки модуля расширения |
| `#S200=zont.microline.ru` | переключение Z3K на тестовый сервер |
| `#S201=52200` | порт тестового сервера |
| `#S200=s1.zont.online,s2.zont.online` | переключение Z3K на рабочие серверы |
| `#S201=55500` | порт рабочих серверов |

При переключении сервера Z3K веб-клиент отправляет адрес, порт, `#S15=1` и
`RESTART` с секундной паузой между строками. Для старых устройств он отправляет
`IPA=<server>`, `IPP=<port>` и `ReStarT`.

Переключение серверов, форматирование файловой системы и обновление прошивки —
опасные служебные операции. Они не нужны интеграции Home Assistant для чтения
состояния или штатного управления и не должны становиться универсальными
сервисами.

## Форматы строк `config.txt`

Пакет `z3k-config-to-text` не выполняет команды непосредственно. Он
сериализует полную конфигурацию в файл `config.txt`; официальный локальный
клиент записывает этот файл через бинарный файловый протокол и затем отправляет
`CFG_RELOAD`.

Основные формы строк:

```text
#S<parameter_id>=<serialized_value>
#Z<object_id>=<object_type>,<serialized_fields>
```

Удаление объекта `#Z<object_id>~` относится уже к исполняемым командам и
описано выше. Для чтения конфигурационной записи используется знакомая форма
`#Z<object_id>?`, но локальный веб-клиент обычно читает целиком `config.txt`.

### Системные параметры `#S`

В исследованном сериализаторе есть следующие 24 ID параметров. В таблице
показана итоговая форма строки; списки и строки дополнительно экранируются
общим сериализатором Z3K.

| Команда/строка конфигурации | Содержимое |
| --- | --- |
| `#S7=<name> <hardware> <firmware>` | имя, аппаратная модель и версия прошивки |
| `#S12=<ussd> <threshold>` | USSD-запрос баланса и порог |
| `#S36=<timezone>` | часовой пояс |
| `#S124=<register>,<speed>,<stop_bits>,<parity>` | настройки RS-485; значения по умолчанию `0,115200,1,0` |
| `#S180=<value>` | диагностический интерфейс A300 |
| `#S181=<value>` | доступные диагностические параметры A300 |
| `#S200=<servers>` | адреса серверов |
| `#S201=<port>` | порт сервера |
| `#S202=<login> <password>` | логин и пароль устройства |
| `#S203=<apn>` | APN |
| `#S204=<password>` | сервисный/USB-пароль |
| `#S206=<notification_or_0>` | настройки GSM-уведомлений |
| `#S207=<phone> <encoded_date>` | сервисный телефон и закодированная дата |
| `#S208=<netname>,<pass>,<0_or_1>` | параметры и признак включения Wi-Fi |
| `#S209=<0_or_1>` | использование резервной батареи |
| `#S211=<id>,<title>,<version>` | штатная конфигурация; заголовок ограничен 200 символами |
| `#S212=<flags>` | флаги серверных настроек |
| `#S214=<name>` | имя локальной подсети |
| `#S217=<address>` | адрес MQTT |
| `#S218=<ssid>,<password>` | точка доступа Wi-Fi |
| `#S222=<0_or_1>` | режим «только 2G» |
| `#S223=<y>,<x>` | координаты в порядке `y,x` |
| `#S225=<10_times_step>` | шаг температуры, умноженный на 10 |
| `#S226=<0_or_1>` | запрет добавления устройств |

Параметры формируются как строки `#S<ID>=...`. Это форматы конфигурации, а не
разрешение изменять их через `scmd`: среди них есть секреты, сетевые настройки
и параметры, способные лишить контроллер связи.

### Типы объектов `#Z`

Source map содержит сериализаторы для 54 типов объектов:

| Тип | Объект | Тип | Объект |
| ---: | --- | ---: | --- |
| `0` | аналоговый вход | `1` | проводной датчик температуры |
| `2` | охранная зона | `3` | уведомление |

| `6` | адаптер котла | `7` | радиомодуль |
| `8` | радиодатчик | `9` | команда |
| `10` | веб-элемент | `11` | сценарий |
| `12` | зуммер | `13` | индикатор охраны |
| `14` | управление реле | `15` | трёхходовой кран/смеситель |
| `16` | контур отопления | `17` | насос |
| `18` | ключ Touch Memory | `19` | роль пользователя |
| `20` | режим отопления | `21` | суточное расписание |
| `22` | недельное расписание | `24` | расширение ввода-вывода |
| `25` | ПЗА | `26` | группа котлов |
| `27` | аналоговый датчик температуры | `28` | температурная кривая NTC |
| `29` | радиобрелок | `30` | кнопка радиобрелока |
| `31` | радиодатчик 433 МГц | `33` | временной интервал |
| `34` | интервальное расписание | `35` | аналоговый DUT |
| `36` | калибровочная таблица | `37` | цифровой DUT |
| `38` | радио-DUT | `39` | панель графика |
| `40` | каскад котлов | `42` | группа интерфейса |
| `43` | массив объектов | `45` | пауза |
| `46` | условный оператор | `47` | компаратор |
| `48` | логическое выражение | `49` | показание датчика |
| `50` | сравнение времени | `51` | устройство Modbus |
| `52` | сигнал Modbus | `53` | аналоговый выход |
| `56` | остановка сценария | `57` | тема MQTT |
| `58` | PID-регулятор | `59` | скриптовый объект |

Наличие сериализатора означает, что общий веб-клиент умеет записать объект
этого типа в конфигурацию. Оно не означает, что тип поддерживается конкретной
моделью контроллера или имеет исполняемую команду состояния `#Y`.

Кроме параметров и объектов, сериализатор счётчиков формирует строки вида:

```text
#Z<combined_id>=*
```

где `combined_id = (Number(key) << 12) | value`. Назначение `key` и `value`
следует устанавливать по модели данных конкретной конфигурации; это не обычный
ID объекта.

## Бинарный файловый протокол

Работа с файлами выполняется не текстовыми командами и не через `scmd`.
Локальный WebSocket-клиент формирует бинарные сообщения со следующими кодами:

| Операция | Запрос | Ответ | Основная нагрузка запроса |
| --- | ---: | ---: | --- |
| открыть файл | `0x40` | `0x41` | имя с `NUL`, режим |
| закрыть файл | `0x42` | `0x43` | дескриптор |
| записать с подтверждением | `0x44` | `0x45` | дескриптор, позиция, данные |
| записать без подтверждения | `0x46` | `0x47` | дескриптор, позиция, данные |
| прочитать | `0x48` | `0x49` | дескриптор, позиция, длина |
| получить список | `0x4A` | `0x4B` | каталог с `NUL`, позиция, количество |
| удалить файл | `0x4C` | `0x4D` | имя с `NUL` |
| создать каталог | `0x4E` | `0x4F` | имя с `NUL` |
| форматировать файловую систему | `0x56` | `0x57` | номер диска |

Режим открытия — битовая маска:

| Флаг | Значение |
| --- | ---: |
| чтение | `1` |
| запись | `2` |
| создать новый | `4` |
| всегда создать заново | `8` |
| открыть или создать | `16` |
| проверить MD5 | `32` |

Позиция записи кодируется как `uint32` little-endian. В запросах чтения и
списка исходный код вызывает `DataView.setUint32` без аргумента little-endian,
то есть использует big-endian. Ответы разных операций разбираются неодинаково;
это следует повторять буквально при реализации транспорта, а не выводить из
одной общей схемы.

Файловые операции нужны веб-клиенту для чтения/записи `config.txt`, прошивок и
служебных файлов. Удаление и форматирование разрушительны и не относятся к
текущему публичному API интеграции.

## Уровень подтверждения и правила использования

- Для проверки полноты по исследованной сборке отдельно проиндексированы все
  явные протокольные литералы `#S`, `#P`, `#Y`, `#Z`, `CFG_*`, команды
  терминала и все модули `z3k-command-to-text`/`z3k-config-to-text`.
  Необъяснённых совпадений, похожих на команды ZONT, после классификации не
  осталось.
- Все 25 преобразований `command_name` подтверждены скомпилированным кодом
  официального веб-клиента ZONT указанной версии.
- Фоновые запросы, справочники терминала, служебные последовательности и
  бинарные коды подтверждены исходным TypeScript из source map приложения.
- Имена сериализаторов `config.txt` подтверждены source map, а итоговые формы
  `#S`/`#Z` — соответствующим скомпилированным bundle. Это конфигурационные
  записи, а не автоматически безопасные команды.
- На контроллере H-1V.02 PRO экспериментально подтверждена индивидуальная
  команда `#Y<circuit_id>=<mode_id>`.
- Остальные команды нельзя автоматически считать проверенными на этой модели
  и прошивке только по наличию в общем веб-клиенте.
- `#Y` имеет типозависимую семантику: одинаковая форма записи означает разные
  действия для режима, контура, реле, охранной зоны и других объектов.
- Перед использованием команды необходимо проверить тип объекта, диапазон и
  допустимые значения аргументов.
- Тестовые команды способны физически включить насос, реле или привод.
- `DIAL` и `SMS` создают внешние действия и могут расходовать средства SIM.
- Команды регистрации, очистки радиомодуля, удаления объекта и перезапуска не
  должны выполняться при обычном обновлении состояния интеграции.
- Универсальный доступ к этим операциям из Home Assistant следует строить на
  явном списке разрешённых команд, строгой валидации и минимально необходимом
  наборе пользовательских возможностей.
