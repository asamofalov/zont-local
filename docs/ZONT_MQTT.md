# ZONT MQTT

Markdown-версия документа [«ZONT_MQTT.pdf»](./ZONT_MQTT.pdf).

## Подключение

MQTT поддерживается в устройствах H2000 PRO V2 и H1000 PRO V2 начиная с
версии прошивки 420. MQTT в ZONT работает через Wi-Fi и Ethernet. Через
мобильную сеть MQTT не работает.

Пример адреса MQTT-сервера с авторизацией:

```text
mqtt://username:password@mqtt.eclipseprojects.io:1883
```

Параметры адреса:

- адрес: `mqtt.eclipseprojects.io`;
- порт: `1883`;
- имя пользователя: `username`;
- пароль: `password`.

Если имя пользователя и пароль не используются, их можно не указывать:

```text
mqtt://mqtt.eclipseprojects.io:1883
```

## Публикация данных

Имя топика формируется из имени настройки топика и имени объекта.

### Датчик

```json
{
  "v": 12.3,
  "a": 1,
  "u": 0,
  "trig": 0
}
```

Поля:

- `v` — значение `float`;
- `a` — доступность датчика: `0` — недоступен, `1` — доступен;
- `u` — единица измерения;
- `trig` — признак срабатывания: `0` — норма, `1` — сработка.

Значения `u`:

| `u` | Единица измерения |
| ---: | --- |
| `0` | Вольт |
| `1` | Ком |
| `2` | Бар |
| `3` | Км/ч |
| `4` | Об/мин |
| `5` | Литр |
| `6` | Литр/час |
| `7` | % |
| `8` | Без единиц |

### Термодатчик

```json
{
  "t": 23.5,
  "a": 1
}
```

- `t` — температура в градусах Цельсия, `float`;
- `a` — доступность датчика: `0` — недоступен, `1` — доступен.

### Радиотермодатчик

```json
{
  "t": 23.5,
  "a": 1,
  "h": 85,
  "b": 100,
  "r": 78,
  "trig": 0
}
```

- `t` — температура в градусах Цельсия, `float`;
- `a` — доступность датчика;
- `h` — влажность;
- `b` — напряжение батареи в вольтах, `float`;
- `r` — уровень сигнала RSSI;
- `trig` — признак срабатывания: `0` — норма, `1` — сработка.

### Отопительный контур

```json
{
  "s": 23.5,
  "c": 1,
  "f": 0,
  "m": "heat",
  "m_id": 4983
}
```

- `s` — целевая температура;
- `c` — текущая температура;
- `f` — состояние неисправности контура;
- `m` — режим работы: `heat`, `cool` или `off`;
- `m_id` — ID текущего режима отопления; `0` означает, что режим не применён
  и используется ручное управление.

### Режим отопления

```json
{}
```

### Реле

```json
{"s": 1}
```

`s` — текущее состояние: `0` — выключено, `1` — включено.

### Насос

```json
{"s": 1}
```

`s` — текущее состояние: `0` — выключено, `1` — включено.

### Смеситель

```json
{"s": 1}
```

Значения `s`:

- `0` — не активен;
- `1` — открытие;
- `2` — закрытие.

### Пользовательский элемент управления

```json
{
  "s": 1,
  "t": "Включено"
}
```

- `s` — текущее состояние: `0` — не активен, `1` — активен; для аналогового
  регулятора содержит его значение;
- `t` — текстовое представление статуса из настроек активного или неактивного
  состояния.

Для аналогового регулятора дополнительно передаются:

- `max` — максимум;
- `min` — минимум;
- `step` — шаг;
- `mul` — множитель значений `min`, `max`, `step` и `s`.

### Адаптер цифровой шины котла

```json
{
  "water": 45.6,
  "dhw": 34.5,
  "return": 30.4,
  "modul": 99,
  "press": 2.4,
  "state": 1,
  "err": 0
}
```

- `water` — температура теплоносителя;
- `dhw` — температура ГВС;
- `return` — температура обратки;
- `modul` — уровень модуляции, %;
- `press` — давление теплоносителя;
- `state` — состояние котла: `0` — выключен, `1` — работает, `2` — ошибка;
- `err` — код ошибки.

### Охранная зона

```json
{
  "s": 0,
  "trig": 0
}
```

- `s` — состояние охраны: `0` — выключена, `1` — включена;
- `trig` — признак срабатывания: `0` — норма, `1` — сработка.

## Подписка и управление

Для управления устройством в сообщении должен быть выбран объект, которому
предназначена команда. Выбрать объект можно одним из трёх способов.

### По ID в сообщении

```json
{
  "Id": 12345,
  "cmd": "command"
}
```

### По имени в сообщении

```json
{
  "name": "Кнопка",
  "cmd": "command"
}
```

### По имени объекта в топике

```text
ZONT/Дом/Управление/Кнопка
```

Для подписки на все подтопики можно использовать wildcard:

```text
ZONT/Дом/Управление/#
```

## Формат `cmd` для разных типов объектов

### Аналоговый вход

| Команда | Назначение |
| --- | --- |
| `0 N T` | Установить значение `N`, заданное в десятых долях вольта |
| `1 N T` | Установить значение `N` как `float` |

Эта возможность применяется к аналоговому входу без привязки к реальному
входу. `T` — время в секундах, в течение которого после сообщения связь с
датчиком считается активной.

### Аналоговый термодатчик

| Команда | Назначение |
| --- | --- |
| `N` | Установить температуру `N` в децикельвинах |
| `0 N` | Установить температуру `N` в децикельвинах |
| `1 N` | Установить температуру `N` в градусах Цельсия, `float` |

Пример перевода `21,5 °C` в децикельвины:

```text
2730 + 215 = 2945
```

### Цифровой термодатчик

Цифровой термодатчик предпочтительнее аналогового.

| Команда | Назначение |
| --- | --- |
| `N` | Установить температуру `N` в децикельвинах |
| `0 N` | Установить температуру `N` в децикельвинах |
| `1 N` | Установить температуру `N` в градусах Цельсия, `float` |

### Охранная зона

| Команда | Назначение |
| ---: | --- |
| `0` | Снять с охраны |
| `1` | Поставить на охрану |
| `2` | Инвертировать состояние охраны |

### Оповещение

| Команда | Назначение |
| ---: | --- |
| `0` | Выполнить настроенное оповещение |

### Действие с выходом

| Команда | Назначение |
| ---: | --- |
| `0` | Выполнить действие с выходом |

### Трёхходовой кран

| Команда | Назначение |
| ---: | --- |
| `1` | Полностью открыть |
| `2` | Полностью закрыть |
| `3` | Открыть на шаг |
| `4` | Закрыть на шаг |

### Контур отопления

Команда `T` задаёт температуру в кельвинах. Пример из исходного документа:

```json
{"cmd": 3000}
```

### Режим терморегулирования

| Команда | Назначение |
| ---: | --- |
| `1` | Установить режим |

### Веб-элемент

| Команда | Назначение |
| --- | --- |
| `0` | Выполнить действия по выключению веб-элемента |
| `1` | Выполнить действия по включению веб-элемента |
| `2,N` | Установить значение аналогового регулятора |

### Сирена, индикатор, реле или насос

| Команда | Назначение |
| ---: | --- |
| `0` | Выключить |
| `1` | Включить |

## Автосоздание объектов

Автосоздание доступно начиная с версии прошивки 500. Для него используется
опциональное поле `type`:

```json
{
  "name": "Кнопка",
  "cmd": "command",
  "type": 10
}
```

Обращение должно выполняться по имени, а не по ID. Если объекта с таким именем
нет, он будет создан с указанным типом и настройками по умолчанию.

Поддерживаемые типы:

| `type` | Объект |
| ---: | --- |
| `0` | Аналоговый вход |
| `1` | Цифровой датчик температуры DS18… |
| `2` | Охранная зона |
| `10` | Пользовательский элемент управления |
| `14` | Реле |
| `15` | Смеситель |
| `16` | Контур отопления |
| `17` | Насос |
| `27` | NTC-термодатчик |
| `53` | Аналоговый выход |

## Чтение данных внешних устройств

ZONT может принимать данные от внешних устройств через брокер. Для этого в
ZONT создаётся виртуальный объект без привязки к физическому входу и ему
назначается топик подписки. Когда внешнее устройство публикует сообщение в
этот топик, ZONT сохраняет значение и отображает его как показание датчика.

Порядок настройки:

1. Создать в ZONT объект нужного типа без привязки к физическому входу.
2. Назначить объекту топик подписки.
3. Публиковать в этот топик сообщения в формате `cmd`.

| Тип данных | Объект в ZONT | Формат `cmd` | Пример |
| --- | --- | --- | --- |
| Температура | Цифровой термодатчик | `1 <градусы float>` | `{"cmd":"1 23.5"}` |
| Аналоговое значение | Аналоговый вход | `1 <значение float> <таймаут>` | `{"cmd":"1 65.0 180"}` |
| Бинарное состояние | Дискретный вход НЗ | `0 <20 или 0> <таймаут>` | `{"cmd":"0 20 180"}` |

Поле таймаута задаёт время в секундах, в течение которого ZONT считает связь с
датчиком активной после получения сообщения.

То же управление подтверждено через локальный WebSocket. Виртуальный объект
создаётся именованной командой с `type=0`, `stype=20`; значение `0` означает
норму, значение `20` — сработку. Подтип `3` с аппаратным назначением
«Датчик открытия двери» для виртуального входа не подходит: напряжение
обновляется, но `trig` не пересчитывается.

ZONT ожидает формат `cmd`. Если устройство публикует данные в другом формате,
например `{"temperature": 23.5}`, нужен посредник: Home Assistant, Node-RED
или скрипт, который читает исходный топик и переопубликовывает значение в
формате `cmd`.

```text
Устройство -> Брокер -> Посредник -> Топик подписки ZONT -> Виртуальный датчик
```

## Интеграция с Home Assistant

В настройках топика можно включить формат Home Assistant. Соответствующие
элементы ZONT автоматически появятся и будут синхронизироваться с интерфейсом
Home Assistant.

### Схема топиков MQTT Discovery

```text
{префикс MQTT Discovery}/{тип объекта}/{серийник}/{id объекта}/{тип топика}
```

- Префикс MQTT Discovery по умолчанию — `homeassistant`. Он настраивается через
  терминал командами `#S221=custom_prefix` и `#S15=1`.
- Тип объекта — `climate`, `button`, `sensor` и другие поддерживаемые типы.
- Серийный номер устройства указан в разделе общих настроек ZONT.
- ID объекта — четырёхзначное число из настроек объекта.
- Тип топика — `state`, `set` или `config`.

Примеры:

```text
homeassistant/sensor/0FF0B0BCEC00/8207/state
homeassistant/button/0FF0B0BCEC00/8194/set
```

Устройство использует wildcard для подписки на все доступные топики управления:

```text
homeassistant/+/0FF0B0BCEC00/+/set
```

### Поддерживаемые компоненты Home Assistant

| Объект ZONT | Компонент HA |
| --- | --- |
| Датчик | `sensor` |
| Датчик температуры | `sensor` |
| Контур отопления | `climate` |
| Пользовательский элемент — статус | `binary_sensor` |
| Пользовательский элемент — простая кнопка | `button` |
| Пользовательский элемент — сложная кнопка | `switch` |
| Пользовательский элемент — аналоговый регулятор | `valve` |
| Насос | `switch` |
| Реле | `switch` |

В именах топиков допускаются русские и английские буквы, цифры, пробелы и
другие стандартные ASCII-символы. Нестандартные символы, например знак градуса
`°`, использовать нельзя: соединение с брокером может быть разорвано.

## Примеры решений для Home Assistant

Примеры ниже перенесены из снимков интерфейса в исходном PDF. Перед применением
проверьте имена entities, топики и синтаксис действий для используемой версии
Home Assistant.

### Передача температуры в децикельвинах

Первый пример исходного документа переводит температуру из Home Assistant в
децикельвины и публикует её в топик `ZONT/Дом/Управление/DT_Спальня`:

```jinja
"cmd": {{ (((states('sensor.datchik_temperatury_spalnia_temperature') | float)
  * 10 + 2730) | int) | string }}
```

### Передача температуры из HA в ZONT

Для цифрового датчика температуры используется команда `1` и значение
температуры в градусах Цельсия:

```yaml
service: mqtt.publish
metadata: {}
data:
  qos: "2"
  retain: false
  topic: "zont/sensors/t/Температура зал"
  payload: >
    "cmd":"1 {{ states('sensor.0xa4c138d3c114d1eb_temperature') | string }}"
```

В ZONT настраивается виртуальный цифровой датчик температуры и его топик
подписки.

### Передача состояния датчика движения

```yaml
service: mqtt.publish
metadata: {}
data:
  qos: "2"
  retain: false
  topic: "zont/sensors/motion/Ванная движение"
  payload: >
    "cmd":"0 {{ 20 if is_state(
      'binary_sensor.0xa4c138765e7844e5_occupancy', 'on') else 0 }} 180"
```

В ZONT настраивается виртуальный датчик «Дискретный вход НЗ».

### Передача состояния датчика открытия двери

```yaml
service: mqtt.publish
metadata: {}
data:
  qos: "2"
  retain: false
  topic: "zont/sensors/door/Ванная дверь"
  payload: >
    "cmd":"0 {{ 20 if is_state(
      'binary_sensor.0xa4c1385efdec5de0_contact', 'on') else 0 }} 180"
```

В ZONT настраивается виртуальный датчик «Дискретный вход НЗ».

### Передача влажности

```yaml
service: mqtt.publish
metadata: {}
data:
  qos: "2"
  retain: false
  topic: "zont/sensors/h/Влажность зал"
  payload: >
    "cmd":"0 {{ states('sensor.0xa4c138d3c114d1eb_humidity') | string }}"
```

В ZONT настраивается виртуальный аналоговый вход.

### Двусторонняя синхронизация выключателей

Для управления Zigbee-выключателем как из Home Assistant, так и из ZONT в
исходном документе использован blueprint:

```text
haade-administrator/2-way-ha.yaml
```

В качестве параметров задаются реальный выключатель и выключатель, публикуемый
из ZONT. В ZONT создаётся пользовательский элемент управления, связанный,
например, с виртуальным реле без назначенного физического выхода, и включается
его публикация в MQTT в формате Home Assistant.
